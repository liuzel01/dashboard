# Signal Monitor v0.2 前端联调说明（现状版）

> 范围：dashboard 前端现有页面（Realtime / History）接入 `price-alert` v0.2 字段。

## 1. 联调目标

- 在不新增子菜单的前提下，直接改造现有页面展示 v0.2 关键信息。
- 保持对历史旧数据兼容（字段缺失时前端兜底显示 `-`）。

## 2. 后端接口与字段

接口：
- `GET /api/signal-monitor/realtime`
- `GET /api/signal-monitor/triggers-24h`

已接入字段：
- `v01_signal_count`
- `v02_direction`
- `v02_score`
- `v02_confidence`
- `v02_should_emit`
- `v02_breakdown`

## 3. 前端改造点（已完成）

### 3.1 Realtime 页面

文件：`eks-dashboard-frontend/src/pages/SignalMonitorRealtimePage.tsx`

- 新增 v0.2 列展示：方向、分数、置信度、建议发送
- 新增 v0.1 对照列：`v01_signal_count`
- 新增可展开行：显示 `v02_breakdown`（factor / bullish / bearish / reason）
- 新增 KPI：`v0.2建议发送数`

### 3.2 History 页面

文件：`eks-dashboard-frontend/src/pages/SignalMonitorHistoryPage.tsx`

- 新增 v0.2 列展示：方向、分数、置信度、建议发送
- 新增 v0.1 对照列：`v01_signal_count`
- 保留原有 v0.1 链路列：`emitted`、`suppressed_reason`
- 新增可展开行：显示 `v02_breakdown`

### 3.3 API 类型

文件：`eks-dashboard-frontend/src/services/signalMonitorApi.ts`

- 补齐 `RealtimeItem` / `TriggerRow` 的 v0.2 字段类型
- 新增 `V02BreakdownItem` 类型定义

## 4. 联调步骤（建议）

1. 启动 `price-alert` API（确保数据文件包含 v0.2 字段）
2. 启动 dashboard 前端
3. 打开 `/signal-monitor/realtime` 与 `/signal-monitor/history`
4. 检查：
   - v0.2 列有值（新数据）
   - 旧数据为空时显示 `-`
   - 展开 breakdown 不报错

## 5. 验收口径（前端侧）

- 页面无报错、无白屏
- v0.2 列可见，且与后端返回一致
- breakdown 展开可用
- 历史旧数据兼容

## 6. 当前边界

- `stats-24h` / `daily-report` 当前仍为旧汇总口径
- v0.2 专项统计展示不在本次实施范围（见后续计划文档）
