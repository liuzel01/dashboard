# Signal Monitor 前端任务拆解清单（MVP）

> 项目：`dashboard`
> 对接后端：`price-alert`（`/api/signal-monitor/*`）

## 0. 目标与边界

- 目标：在 dashboard 新增 `Signal Monitor` 菜单，提供可复盘的信号看板。
- 边界：
  - 前端只做展示与交互。
  - 不在前端实现策略、降噪、交易逻辑。

---

## 1. 接口清单（已可用）

1. `GET /api/signal-monitor/realtime`
2. `GET /api/signal-monitor/triggers-24h`
3. `GET /api/signal-monitor/stats-24h`
4. `GET /api/signal-monitor/daily-report?date=YYYY-MM-DD`

后端参考：
- `price-alert/docs/17-任务14-后端接口联调最小清单.md`

## 2. 任务分解（按交付顺序）

## T1 菜单与路由骨架
- [ ] 新增一级菜单：`Signal Monitor`
- [ ] 新增子路由：`/signal-monitor/realtime`
- [ ] 新增子路由：`/signal-monitor/history`
- [ ] 预留路由：`/signal-monitor/stats`、`/signal-monitor/daily`

## T2 API 客户端封装
- [ ] 新增 `signalMonitorApi`（统一请求封装）
- [ ] 定义 TS 类型：Realtime/History/Stats/Daily
- [ ] 统一错误处理与超时配置

## T3 Realtime 页面（优先）
- [ ] 顶部 KPI：active 数、高优先级数、最近触发时间
- [ ] 主表格字段：symbol/timeframe/rule/priority/latest_price/latest_trigger_time
- [ ] 自动刷新（30~60s）
- [ ] loading/error/empty 态

## T4 History 页面（优先）
- [ ] 查询参数：symbol/rule/timeframe/priority/page/pageSize
- [ ] 列表字段：event_time/direction/emitted/suppressed_reason/dedupe_key
- [ ] 分页、筛选、重置
- [ ] 导出 CSV（可选 MVP+）

## T5 Stats 页面
- [ ] 卡片：trigger_count/emitted_count/suppressed_count/send_success_rate
- [ ] 图表：by_rule、suppressed_breakdown
- [ ] 空数据兜底

## T6 Daily 页面
- [ ] 日期选择器
- [ ] 请求 `/daily-report?date=...`
- [ ] Markdown 渲染
- [ ] 一键复制/下载

## T7 联调与验收
- [ ] 对照后端联调最小清单逐接口验证（待执行）
- [ ] 截图留档（四页面）（待执行）
- [ ] 记录已知问题与后续优化项（待执行）

## 3. 建议迭代计划

- Iteration-1：T1+T2+T3+T4（先可用）

## 4. 验收标准（MVP）

- 可查看实时信号状态
- 可筛选并分页浏览 24h 记录
- 可查看基础统计和日报内容
- 页面异常状态可理解（非白屏）
